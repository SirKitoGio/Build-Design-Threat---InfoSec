Cognitive load is high: 5 of 8 checks fail. Single focus fails because an empty desk still shows New event, Your events, and a second card telling you to create an event when Door Night is already listed, and Register is identity, two passwords, and role on one screen. Chunking fails on seven password rules and five register fields in one group. Visual hierarchy fails because the sign-in H1 is an acronym and a closed or invalid check-in is quieter than the button. Minimal choices fails on the live desk: Copy link, Close check-in, Refresh list, New event, and Log out at once. Working memory fails because the reset code leaves the screen before Choose a new password, and a check-in URL bounces to a generic /auth with no event name. Grouping, one-thing-at-a-time on the reset steps, and progressive disclosure of the password rules pass.

The emotional peak is missing. The yellow primary and “sent to jordan303@tarantech.club” are reassuring. A successful scan was not reachable (the only event was already closed). The closed door reads as a disabled form. An invalid code still offers a yellow Check in. A wrong reset asserts that a code was sent, collects a new password, then says the code is not valid.

## Overall Impression

The club door is already in this interface, and the account kit is sitting on top of it. What works is the quiet desk once an event is open, the password rules that refuse a weak account, and a close flow that asks before it shuts the door. What fails is the moment that matters: check-in still looks like a form with a caption, and password reset spends a new password before it admits the code was wrong. The single biggest opportunity is to make “you’re in”, “this door is closed”, or “this is not a TaranTech code” the whole page.

## What's Working

- **Password rules.** An X becomes a check, the row is announced “Not yet” or “Passed”, the list appears only after typing, and Create account / Save new password stay disabled until every rule passes. “Attendees scan in. Organizers run the door.” makes Role a real choice.
- **Close check-in.** The first click opens “Attendees will not be able to check in.” with Confirm close and Cancel. The QR stays up until the organizer confirms.
- **The live desk.** Door Night, the QR, OPEN, “0 checked in”, and “Waiting for the first scan.” are the product. Scan to check in on the attendee page is one full-width yellow button with a camera mark.

## Priority Issues

### [P1] The door result is a caption under a button

On a closed event the button is a pale Check in under “No description”. On a bad link the heading stays “Event” and Check in stays enabled. An organizer who opens their own QR gets only “Log in as an attendee to check in.” and Back to organizer desk, with no event name. A success state was not on screen; in source it is a green sentence, “Checked in as {name} at {time}”, with no status role, and the button remains.

**Why it matters.** This is the moment at the door. A caption under a still-clickable button does not tell someone they are in, or that they should stop trying.

**Fix.** Make the result the page. One line: you’re in, this door is closed, or this is not a TaranTech code. Hide Check in when it cannot work. Drop “No description”. Announce the outcome as a status.

**Suggested command.** `$impeccable clarify`

### [P1] Reset checks the code only after the new password

Continue on the code step only checks length. Choose a new password then says “That code is not valid.” The code is gone. Use a different email is the way back, and it clears the address. Unknown addresses still get “Enter the 6-digit code sent to {email}.” The hedge “If that email is on an account, a code was sent.” sits under that assertion.

**Why it matters.** A wrong or missing code costs a password the person just invented, then offers a detour that throws the email away.

**Fix.** Verify the code before the password. Keep the code on screen. Add Edit code. Make the headline match the hedge.

**Suggested command.** `$impeccable harden`

### [P1] A check-in link lands on a sign-in whose headline is AWSSBGJRU

`/checkin/:token` while logged out becomes `/auth` with Log in, Username or email, and Continue. The return works after an account exists (jordan303 landed on Door Night), but the wall never names the event. The H1 is the acronym. The useful line, “QR attendance for club events”, is the tagline.

**Why it matters.** Someone at the door cannot tell this screen is the check-in for the night they just scanned.

**Fix.** When a check-in is pending, headline “Check in” and name the event when the preview can be shown without a session. Otherwise say “Sign in to check in.” Move AWSSBGJRU to the eyebrow next to ITC 303.

**Suggested command.** `$impeccable clarify`

### [P2] Placeholders look filled in

`#6b76a0` on white is dark enough that empty Username, Email, Code, and Title read as `keith`, `keith@tarantech.club`, `000000`, and `Club Night`.

**Why it matters.** People skip a field they think they already typed, or they try to log in as the sample.

**Fix.** Lighten the placeholder and put the example under the label.

**Suggested command.** `$impeccable typeset`

### [P2] The desk tells you to create an event that already exists, then prints the raw link

With Door Night in Your events and nothing selected, the right card still says “Create an event to put a QR on the door.” The selected row is bold only. Under the QR, Check-in link is the full localhost URL.

**Why it matters.** The organizer has to notice a text button to put the code on the door, and the URL is a developer string, not a door tool.

**Fix.** When events exist, the stage says “Open Door Night.” Mark the current row with more than weight. Keep Copy link. Do not show the token string.

**Suggested command.** `$impeccable layout`

## Persona Red Flags

The current event is bold text on Door Night, with no `aria-current`. The first screen is still the full New event form when a list already exists. The thing under the QR is the raw token URL.

Empty register says “Meet the password rules to continue.” before any rules are visible. Placeholders look typed. Closed Door Night shows “No description” and a pale Check in. The history empty state is “None yet.”

**Sam (keyboard and screen reader).** Log in / Register are buttons, not a tablist, and the tree does not say which is selected. Both password rows expose a button named only Show.
