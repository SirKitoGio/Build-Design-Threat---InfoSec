## Overall Impression

The palette is doing its job. The screens before the door are still a generic account form, and the door itself will not get out of the way of the QR. The single biggest opportunity is the event desk: once an event exists, the only job on that screen is holding the code up to the room.

## What's Working

- Gas is rationed. It is the brand card, the active tab, and the one primary. Cadet on white is about 14:1. The attendee home is one yellow Scan to check in button and a quiet list.
- The password rule marks tell the truth in shape. An X becomes a check, the row is announced as Not yet or Passed, and Create account will not submit early.
- A failed sign-in speaks plainly. The pink alert reads "Username or password is not correct," the fields stay filled, and Continue shows Working… while it waits.

## Priority Issues

**[P1] The event desk will not get out of the way of the QR.**
Why it matters: After an event exists, New event still owns the left half on a desktop and the whole first screen at 375px. The QR starts below the fold on a phone. The thing the room needs is under a form that already succeeded.
Fix: Collapse New event once an event is open. Give the QR the width of the phone, the event name, the Open pill, and the attendance count. Leave create under a single New event control.
Suggested command: $impeccable layout

**[P1] Confirm close is a label change on a harmless-looking button.**
Why it matters: The second click uses the same white fill as Refresh list, in the same row. Nothing says attendees will be locked out. There is no Cancel.
Fix: Make the second step a danger control, with one line of consequence and a Cancel that restores Close check-in.
Suggested command: $impeccable clarify

**[P1] The password wall punishes an empty form, then stacks the next task on top.**
Why it matters: Seven red marks show before a character is typed. Create account and Save new password go pale yellow, about 2.6:1, and never say why they are off. Reset asks for the code and a new password in one scroll, and the email looks like a normal field while it is disabled. The code step says "Check your email" and does not name the address.
Fix: Show the marks as the person types. Keep the disabled button at full contrast and say what is missing. On reset, ask for the code, then the password. Name the address. Add Resend code, which sign-in already has.
Suggested command: $impeccable polish

**[P1] The live UI talks like the repo.**
Why it matters: The desk header pill reads PW · BCRYPT+SALT. The empty stage says the QR encodes a random token, not a sequential id. The code step's green bar says Local demo code. The paste field's placeholder is a localhost URL, and placeholders are dark enough to look typed.
Fix: Take the storage pill and the token sentence off the desk. If a demo code must show, style it as a lab note and name the inbox. Lighten placeholders so an empty Title no longer looks like Club Night.
Suggested command: $impeccable clarify

**[P2] The check-in ending undersells the only moment that matters.**
Why it matters: Success is a small green sentence under a Check in button that is still enabled. The policy line "Closed events stay closed" sits under the success, and the timestamp wraps so AM lands on its own line.
Fix: Replace the button with a finished state, drop the seconds, and move the policy off that screen. Announce the success to a screen reader.
Suggested command: $impeccable polish
